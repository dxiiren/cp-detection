# Development workflow

> **TL;DR** Strict TDD — no implementation file before a test that fails for the right reason.
> Vitest is the inner loop (`just watch`), Playwright is the outer loop and the only layer with a
> real clipboard, and `just verify` (typecheck, lint, vitest, playwright) is the gate before every
> push. `just test` passing is not "done" — three real bugs sailed through jsdom.

## The working agreement

The repo is built TDD, strictly: red → green → refactor, and the red output gets shown, not
asserted. The acceptance specs in `tests/e2e/` were written first and define done. `CLAUDE.md` at
the repo root records the contract those specs assume — testids, field ids, toast wording, the
hydration flag — read it before changing the detector or the playground markup.

## The two loops

| Loop  | Runner                       | What it covers                                                | Command      |
| ----- | ---------------------------- | ------------------------------------------------------------- | ------------ |
| Inner | Vitest, project `unit` (node) | Pure logic: attribution, redaction, stores, seo, theme, toast copy | `just test-unit` |
| Inner | Vitest, project `dom` (jsdom) | The DOM adapter and React bindings (`*.dom.test.{ts,tsx}`)    | `just test-dom`  |
| Outer | Playwright, Chromium only    | Real `ClipboardEvent`, real granted clipboard permissions — the definition of done | `just e2e` |

`just watch` is the inner TDD loop. The file naming carries the split: `*.test.ts` runs in node,
`*.dom.test.ts`/`*.dom.test.tsx` runs in jsdom (and is excluded from the node project so it does
not run twice — see `vitest.config.ts`).

Why the outer loop is non-negotiable: three real bugs passed every jsdom test and were caught only
by Playwright — the write-only `clipboardData` during copy/cut (every copy logged 0 chars),
per-page record ids colliding with the server's dedupe (most events silently discarded), and
elapsed-time echo matching that both double-logged and swallowed pastes under load. The root
README's Testing section tells each story in full.

## The gate

```
just verify        # typecheck -> lint -> vitest -> playwright, cheapest first
```

Run it before pushing. There is no CI in this repo, so this gate is the only one. Narrower
commands while iterating: `just typecheck`, `just lint`, `just fmt` (prettier + eslint --fix),
`just e2e-file <filter>` for one spec, `just e2e-headed` / `just e2e-ui` to watch or debug,
`just e2e-report` for the last run's traces.

## Writing E2E specs

- **Wait for hydration before acting.** Detection is installed in an effect; a paste fired against
  server-rendered markup lands natively and is silently missed. Every spec starts with
  `await expect(page.getByTestId('playground')).toHaveAttribute('data-detecting', 'true')`.
- **Navigate with `navigateTo(page, 'Events')`** from `tests/e2e/helpers.ts`, not a bare
  `getByRole('link', ...)` — the landing copy and footer also link to the events log, and an
  unscoped locator fails strict mode. The helper scopes to `<nav aria-label="Main">`.
- The suite runs **2 workers** on purpose (`playwright.config.ts`): every worker loads pages from
  one Vite dev server and the axe scans are CPU-heavy; four workers intermittently starved the
  server. Do not raise it to "speed things up" — slower and deterministic is the trade a gate is
  for.
- Chromium only: clipboard permissions are not grantable in Firefox or WebKit.

## Routes and generated files

- Adding or renaming a file in `src/routes/` regenerates `src/routeTree.gen.ts` automatically while
  the dev server runs; run `just routes` manually when only typechecking. Never hand-edit it.
- Server routes with dots in the path use brackets — `robots[.]txt.ts` — because the router reads a
  dot as a path separator.
- `public/` (favicons, `og.png`, manifest) is generated by `just assets` and **committed**; only
  re-run it when the mark, palette or share-card copy changes.

## UI components

`just ui dialog tooltip` adds shadcn components. Style and aliases come from `components.json` —
the import alias is `#/`, not `@/` (both resolve, `#/` is the convention). New components land in
`src/components/ui/`.

## Conventions

| Convention        | Rule                                                                    |
| ----------------- | ----------------------------------------------------------------------- |
| Import alias      | `#/*` → `./src/*`                                                       |
| Package manager   | pnpm — never npm/yarn against this lockfile                             |
| Formatting        | Prettier + ESLint (TanStack config); `just fmt` writes, `just check` verifies |
| Line endings      | `.gitattributes` normalises to LF (CRLF for `*.ps1`); do not fight it   |
| Pure/adapter seam | Non-determinism goes in adapters; pure modules take injected clocks     |
| Dev server        | Prefer `just start` over `just dev` — a stale server imitates a hydration bug |
